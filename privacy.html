opencode-google · Google API Services

Privacy policy

This policy covers opencode-google, the local MCP server distributed at github.com/YsinHsim/opencode-google, and the other installers in the opencode suite.

Last updated: 25 October 2026

The short version

opencode-google is software you run on your own computer. It is not a hosted service. Your Google data goes from your machine to Google's APIs and back. It is never sent to a server operated by this project, because no such server exists. There is no account to register and no backend that receives your data.

There is no “opencode suite” cloud. The repository, this website, and the installer are the only things published. All Google API traffic originates from the user's own device and terminates at Google.

What data is accessed

When you run auth.py, you grant an OAuth client that you created in your own Google Cloud project access to the following scopes. Each one is the narrowest that still supports the feature described.

ScopeData reachedWhy it is needed
calendar.events Event titles, times, attendees, locations, descriptions Read your schedule, find free slots, create events, and move or delete an event after you approve a preview
gmail.readonly Message and thread contents, headers, labels Search your mailbox and read a thread you asked about. The server has no ability to send, compose, or modify mail
drive.file Only files this app created Upload generated files and list what the app itself put there. Google restricts this scope to app-created files; the rest of your Drive is not reachable
documents Docs the app creates or opens Create and append to documents in the app folder, and read them back
spreadsheets Sheets the app creates or opens Create spreadsheets, read ranges, append rows
tasks Task titles, notes, due dates List tasks, create tasks, mark them complete
contacts.readonly Contact names, emails, phone numbers Look up a person by name so an event can be addressed correctly. Read-only

How data is used

Google user data is used for exactly one purpose: answering the request you made in your own OpenCode session, on your own machine. For example, resolving “move the HSSB call to Friday 3pm” by reading the event you named and writing back the new time.

Google user data is not used to:

  • Train or improve any machine learning model operated by this project;
  • Build a profile, advertise, retarget, or determine credit-worthiness;
  • Produce analytics about you or your organisation;
  • Provide any feature you did not ask for in that session.

How data is stored

Two credential files are written to your machine, both outside the repository and both with file mode 0600 (owner read/write only):

  • ~/.config/opencode/google/client_secret.json — the OAuth client you created;
  • ~/.config/opencode/google/token.json — the refresh token issued after you consent.

Both paths are gitignored. No Google user data is written to disk by this server beyond whatever Google's own client libraries cache in the access token. Content you ask it to read is held in memory for the duration of the request and is not persisted by the server.

Files the app creates in Google Drive, Docs or Sheets are stored in your Google account, inside a folder named opencode, under your normal Google terms. Delete them whenever you like; the app loses access as soon as you move them out of that folder.

How data is shared

It is not. The project operates no server that could receive your data. Your machine talks directly to Google's API endpoints over TLS.

There is one nuance worth stating plainly: the code in your OpenCode session is executed by the model provider you configured. If an MCP tool result is included in the conversation that provider sees, that content reaches that provider under its own terms. Choosing your provider, and what you ask the agent to read, is the control you hold there. This server does not send anything to a model provider itself.

Google API Services User Data Policy

opencode-google's use and transfer of information received from Google APIs adheres to the Google API Services User Data Policy, including the Limited Use requirements. Specifically:

  • Data is used only to provide the user-facing feature the user requested.
  • Data is not transferred to third parties except as necessary to provide that feature, for security purposes, or to comply with law.
  • Data is not used for advertising, and is not sold.
  • No human reads your Google data. The project has no access to it; only you do.
  • Narrow scopes are requested. Gmail is read-only; the Drive scope is limited to app-created files.

Your control

  • Revoke access at myaccount.google.com/permissions. This takes effect immediately and no reinstallation is needed.
  • Delete the token by removing ~/.config/opencode/google/token.json.
  • Delete the client by removing the OAuth client in your own Google Cloud project. You created it; it belongs to you.
  • Read the code. The repository is public; the scope list is in lib/google_clients.py and the full operating rules are in SOP.md.

Children

opencode-google is a developer tool intended for adults. It is not directed at children under 13 and does not knowingly process their data.

Changes to this policy

Any change to how Google user data is handled will appear on this page with a new “last updated” date, and in the repository's commit history. Because the software runs locally, you can always read the exact version you are running.

Contact
