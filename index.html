Your agent, finally knows your work. ✦ しごと

OpenCode is sharp but blind. It can't see your tickets, your inbox, or your calendar. These installers fix that with local MCP servers — each owning exactly one secret and one config entry, so you can add, update or remove them independently.

New here? Start with the base installer's --interview mode: it asks a handful of questions and writes a config for your provider — OpenAI, Anthropic, Ollama, or any OpenAI-compatible endpoint. Then add Google or Aztra only if you want them.

The gap

A great agent with
no context.

You open OpenCode, ask it to book a slot, and it asks which calendar. Ask it about a client email and you paste it in by hand. Every session starts from zero because the agent can't reach the systems where your actual work lives.

The usual fix is a hosted integration that wants your whole Google account and a monthly fee. This suite takes the other route: small servers on your own machine, talking directly to the APIs, holding the narrowest scopes that still do the job.

Why this doesn't need blind trust

Every action is
a class.

The safety model is enforced in code, not by asking the model nicely. A destructive action cannot execute on its first call even if the prompt says it should.

✦ Class R

Do it, then report

Creating is additive. If it goes wrong you delete the result yourself. All reads are Class R by definition.

✦ Class C

Preview, then wait

The first call does nothing. It returns a field-by-field before/after and a one-time token bound to that exact payload. Change a value and the token is refused.

✦ Class X

No tool exists

No send-mail. No permanent delete. No changing sharing or ownership. If you ask, it explains the manual path in the UI instead.

01

Drive is fenced

Uploads land only in one opencode/ folder. The drive.file scope means Google itself limits access to files the app created. A path outside the fence is refused in code.

02

Narrow scopes, on purpose

Gmail is readonly. Draft creation needs gmail.compose and is deliberately not requested. YouTube was excluded because search.list costs 100 units against a 10,000/day quota.

03

Secrets stay off the repo

Keys are read at runtime through {file:…} references, so opencode.json is safe to commit, sync or share. Nothing secret is written into a config file.

04

Write provenance

Files the agent creates carry an [OpenCode] title prefix. Anything without it is treated as your own work: readable, but never rewritten.

Install

One clone
per repo.

Each installer detects your platform, backs up the live config before touching it, and only writes under ~/.config/opencode and the repo directory.

Before you start: git, python3, and a Google account. The Google Cloud Console setup is a one-time ten minute step with no billing account and no credit card.
zsh — install 
# 01 — base: your provider, your keys, your rules
$ git clone https://github.com/YsinHsim/opencode-bootstrap.git
$ cd opencode-bootstrap && ./install.sh --interview

# 02 — company: prompts for your Aztra key
$ git clone https://github.com/YsinHsim/opencode-aztra.git
$ cd ../opencode-aztra && ./install.sh

# 03 — google: browser OAuth, then create the Drive folder
$ git clone https://github.com/YsinHsim/opencode-google.git
$ cd ../opencode-google && ./install.sh
$ source .venv/bin/activate && python auth.py
$ python setup_check.py --setup
$ python setup_check.py --selftest

In practice

Things you can
just ask.

→

“What's on my calendar this week?”

Reads the window you name. Silence is the correct answer when nothing is on.

→

“Find me a 90 minute free slot on Thursday”

Gaps inside working hours, Mon–Fri, defaulting to Asia/Kuala_Lumpur.

→

“Move the HSSB call to Friday 3pm”

Class C. You see the before/after, say yes, and only then does it move.

→

“Any unread email from clients in the last 2 days?”

Gmail syntax, capped results. One thread at a time, not the whole mailbox.

→

“Make a CR for the sales order monitor and upload it”

Creates the Doc inside opencode/ and hands you the link. Moving it out afterwards is expected.

Who runs this

Built on one
real desk.

The opencode suite is a toolset by Yasin Hassim, a software developer and system analyst in Kota Kinabalu, Sabah, Malaysia — written for his own desk first, and made public so anyone can run the same setup.

It started as a way to stop re-pasting context into every session: tickets in one system, schedule and inbox in another, and an agent that could see neither. Each installer is small, does one thing, and owns exactly one secret — so the whole thing stays auditable in an afternoon.

The repos are public and readable. There is no account to create and no data sent to a server operated by this project, because no such server exists.
